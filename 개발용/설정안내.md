# 자세한 설정 안내

처음 사용하는 방법은 [README](../README.md)에 있습니다. 이 문서는 분류를 바꾸거나 프로그램을 관리할 때만 참고하세요.

## 지원 환경과 보고서 기준

Windows 10/11의 Windows PowerShell 5.1에서 사용합니다. 같은 Atlassian Cloud 사이트에서 Jira와 Confluence를 사용해야 합니다. 서로 다른 사이트나 자체 설치 서버는 지원하지 않습니다.

- 진행 중 상태 범주의 본인 이슈는 날짜 제한 없이 포함합니다.
- 완료 범주는 이번 주 월요일부터 실행 시점까지 완료 처리된 이슈만 포함합니다.
- 신규 범주는 이번 주 업데이트된 이슈를 포함합니다.
- 페이지당 100개씩 전체 조회한 뒤 제외 상태를 걸러냅니다.
- 완료 이슈의 일정은 완료일, 나머지는 마감일입니다. 차주 칸은 비워 둡니다.
- 같은 스페이스에서 같은 날짜·이름의 보고서를 찾으면 본문 전체를 덮어씁니다.

이 도구는 범위 없는 API 토큰으로 사이트 주소에 인증합니다. 범위가 지정된 토큰의 별도 gateway 인증은 지원하지 않습니다. [Atlassian 공식 안내](https://support.atlassian.com/confluence/kb/scoped-api-tokens-in-confluence-cloud/)를 참고하세요.

## 분류 규칙 바꾸기

설정 후 실행 폴더에 생긴 `weekly_report.rules.psd1`을 열어 수정하고 **UTF-8 BOM**으로 저장하세요.

```powershell
CATEGORIES = @(
    @{ NAME = '개발'; PROJECT_KEYS = @('DEV'); KEYWORDS = @('개발', '기능 추가') }
    @{ NAME = '문의'; KEYWORDS = @('문의') }
)
DEFAULT_CATEGORY = '기타'
CATEGORY_ORDER = @('개발', '문의', '기타')
EXCLUDED_STATUSES = @('HOLDING')
```

위 코드는 설정 파일 안의 해당 항목을 바꾸는 예시입니다. 파일 전체를 이 내용으로 교체하지 마세요.

프로젝트 키 또는 제목 키워드 중 하나라도 맞으면 분류하며 위쪽 규칙이 우선합니다. 키워드는 대소문자를 구분하지 않고 문자 그대로 검색합니다. 조건이 없는 분류와 중복 이름은 허용하지 않습니다. 아무 규칙에도 맞지 않으면 기본 분류로 갑니다. 기본 분류는 `CATEGORIES`에 중복 등록하지 않습니다.

`CATEGORY_ORDER`는 표 순서입니다. 새 분류를 적지 않으면 뒤에 추가됩니다. 분류를 삭제하면 표시 순서에서도 지우세요. `IGNORE_TEAM_PREFIX = $true`이면 `(개발팀)`처럼 '팀'으로 끝나는 제목 앞 괄호는 일반 분류 검사에서 제외하며 원래 표시 제목은 유지합니다.

여러 티켓을 한 행으로 묶으려면 다음처럼 설정합니다.

```powershell
GROUP_RULES = @(
    @{ KEYWORD = '정기 점검'; LABEL = '정기 점검'; CATEGORY = '기타'; SCHEDULE = '~{FRIDAY}'; STATUS = '진행중' }
)
```

묶음 규칙은 일반 분류보다 우선하며 처음 맞는 묶음에만 들어갑니다. `CATEGORY`는 정의된 분류나 기본 분류여야 합니다. `{FRIDAY}`는 이번 주 금요일의 `MM/dd`로 바뀝니다. 일정과 상태는 지정한 문구이며 개별 티켓의 값을 합산하지 않습니다. 필요 없으면 `GROUP_RULES = @()`로 둡니다.

## Jira 매크로 표시

기본적으로 클릭 가능한 이슈 링크를 표시합니다. 매크로가 필요하면 `weekly_report.config.psd1`의 `SERVER_ID`에 Confluence의 Jira application link ID를 넣습니다. 사이트 관리자에게 확인하세요.

## 업데이트와 자동 실행 해제

- 새 ZIP의 `app` 폴더, 실행 파일 두 개, README, `개발용` 폴더를 기존 폴더에 덮어씁니다. 개인 설정·개인 규칙은 그대로 둡니다.
- 이전 버전에서 업데이트했다면 `처음설정.cmd`를 실행해 기존 설정은 유지하고 자동 실행을 다시 등록하세요. 작업이 새 프로그램 경로를 사용하게 됩니다. 이전 버전의 남은 코드·기본설정 폴더는 사용하지 않습니다.
- 폴더를 옮기면 Windows 작업 스케줄러에서 이전 작업을 삭제한 뒤 새 위치에서 자동 실행을 다시 등록하세요.
- 자동 실행 해제는 작업 스케줄러의 `WeeklyReport-…` 작업을 사용 안 함으로 바꾸거나 삭제합니다. 작업 이름은 설정 완료 시 표시됩니다.
- 과거에 직접 만든 `WeeklyReport` 작업이 있다면 중복 실행되지 않도록 별도로 해제하세요.

## 파일 역할과 검증

| 위치 | 역할 |
| --- | --- |
| `처음설정.cmd` | 처음 설정 시작 |
| `지금실행.cmd` | 보고서 바로 생성 |
| `app/setup.ps1` | 입력 안내, 개인 설정·기본 규칙 생성, 선택적 예약 등록 |
| `app/weekly_report.ps1` | Jira 조회와 Confluence 보고서 저장 |
| `개발용/verify_rules.ps1` | 계정 없이 오프라인 검사 |

설정 보조 함수와 기본 규칙은 설정 스크립트에 포함되어 있습니다. 별도 양식 파일은 필요 없습니다. 개인 설정·규칙·로그는 실행 폴더에 만들며 Git에서 제외합니다. 개인 설정에는 토큰이 평문으로 저장되므로 공유하지 마세요.

실행 폴더에서 다음 명령을 사용합니다.

```powershell
# 계정·네트워크·예약 등록 없이 코드 검사
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\개발용\verify_rules.ps1

# Jira 조회만 확인 (보고서는 변경하지 않음)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\app\weekly_report.ps1 -Preview
```

Preview는 Confluence 권한이나 최종 보고서를 확인하지 않습니다. 실제 저장 성공 여부는 첫 보고서를 생성해 확인하세요.
